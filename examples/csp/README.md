# Solas CSP example

A small app that enforces a nonce-based Content Security Policy in production.

The CSP is generated in `app/+middleware.ts`:

- production: `script-src 'self' 'nonce-...' 'strict-dynamic'` and
  `style-src 'self' 'nonce-...'`
- development: relaxed for Vite HMR and React's development tooling

## Run

From the repo root:

```sh
bun install
```

Then, from this directory:

```sh
bun run dev       # relaxed CSP on http://127.0.0.1:4322
bun run build     # production build
bun run start     # strict CSP on http://127.0.0.1:4322
```

Stop `dev` before `start`; both use port 4322.

## What to check

Open the app in production and navigate from `/` to `/styles` and `/cxx` with
the client router.

- The document response has a `Content-Security-Policy` header with a nonce.
- Solas reads the hidden `.nonce` property from a nonced script or style; the
  nonce is not exposed as a normal attribute or meta tag.
- The layout's inline `<style>` has the same nonce.
- The `/styles` page renders a hoistable `<style href precedence nonce>`.
  React only keeps the rules when the tag and the renderer use the same nonce.
- The `/cxx` page renders a style generated by `@jk2908/cxx`. The tag is written
  by the app, so it passes the nonce explicitly:
  ```tsx
  <style href={href} precedence="medium" nonce={nonce}>
  	{css}
  </style>
  ```
- Navigating between the routes keeps both styles working. The browser router
  sends the document nonce as `x-solas-nonce` on the RSC request, so the new
  payload is rendered with the nonce the document already enforces.

The `/styles` page is a plain React hoistable style. `@jk2908/cxx` returns the
same kind of tag, so its style needs the same `nonce` prop.

If you do not need strict style nonces, keep the nonce for scripts and use
`style-src 'self' 'unsafe-inline'`; then CSS-in-JS needs no nonce plumbing.

Full prerenders served by Solas receive automatic hashes for their inline scripts
and styles, so a nonce CSP can still work when those routes are cached. For full
hash-only responses, use `script-src 'self'` rather than `'strict-dynamic'`,
because browsers do not carry hash trust into a dynamic `import()`.

PPR receives hashes for its cached shell and a request nonce for its dynamic
holes, so it can keep `'strict-dynamic'`. The static adapter does not receive
automatic hashes yet; use hashes or Subresource Integrity for that, or keep the
route dynamic.
